This is a project to create a standalone network adaptor based around an ESP32 microcontroller (in effect, accomplishing the same functionality as the [tap-slip-gw application](/tap-slip-gw) but without needing a Linux box. 

Initially I had planned to use the [ESP32 Ethernet kit](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32/esp32-ethernet-kit/user_guide.html) for this, then I cam across the [Waveshare ESP32-S3-ETH board](https://www.waveshare.com/wiki/ESP32-S3-ETH#ETH_Web_CAM) which is not only [much cheaper](https://thepihut.com/products/esp32-s3-ethernet-development-board-rj45) but also smaller as well. 

Here's the initial test setup:

![PXL_20250601_102112606 MACRO_FOCUS](https://github.com/user-attachments/assets/5fcf4067-0946-4368-867c-8a1e0430ecfb)

In this instance, I'm using a Raspberry Pi instead of the Dragon because both the ESP32 and the Pi use 3v3 logic levels. Hence it's a very straightforward setup to use in order to start prototyping the software.

The Pi is running a copy of [tap-slip-gw](/tap-slip-gw), routed to it's onboard serial port, /dev/ttyAMA0. The ESP is using a slightly modified version of the _ESP32 Ethernet Library_ (EthClass) which essentially just disables the attaching of the TCP/IP stack to the driver. Essentially then all the application code does is forward raw Ethernet frames to/from the serial interface attached to the Pi. 

Modern Ethernet adapters automatically filter out non-broadcast frames that aren't intended for them so there is some additional logic in play to change the MAC address of the card to match that be used by the serial attached client. 

With the basic software functionality proven, the next step was to add a RS232 transceiver to convert between the +/-12v levels generated by the Dragon to/from the UART on the ESP32. For this I'm using a [MAX3232 chip](https://www.analog.com/en/products/max3232.html):

![PXL_20250607_094851640 MACRO_FOCUS](https://github.com/user-attachments/assets/f34a7071-09e1-4ef4-8788-419be47bd4ed)

This provides two transceivers, the intention is to use 1 pair for the TX/RX lines and the other for the control signals (RTS/CTS). For the initial tests, I used a USB/Serial adaptor to connect this to a Linux box, again running [tap-slip-gw application](/tap-slip-gw)

Finally, time to connect it to the Dragon:

![PXL_20250608_110305615](https://github.com/user-attachments/assets/52eee7e1-8b7a-44ce-a136-13f9c20652be)

As it stands then, it's basically working. There's still a few issues to sort out, one of which being some odd behaviour with the voltage levels around the MAX3232 chip which is causing spurious characters to be received by the Dragon. As a result, I've not yet had it working with hardware flow control wired up.
